Latent-universal machines

The latent-universality theorem says that models with a fixed rule and a fixed interface can compute any computable function by changing only the program. LUTM-1, LUTM-6 and LU-A are small, concrete machines of this kind, built to measure how hard their programs are to find.

The idea

A substrate is latently universal if every computable function already exists somewhere in its space of programs, under one fixed interface. Four properties separate this from ordinary Turing completeness:

  • The interface is program-blind. Rule, encoder, halting condition and decoder never change. The input is written literally next to the program and the output is read literally; the interface never looks at the program, so it cannot do part of the work.
  • Every string is a program. Nothing is parsed or rejected. The whole space of strings is valid, and that space is the search space.
  • Exactness. For each computable function there is a finite program that is correct on all inputs, of every length, and halts exactly where the function is defined.
  • Existence, not accessibility. The theorem says nothing about the size of the program or how hard it is to find. The capability sits in the rule and stays dormant until a search finds it; hence “latent”.

Ordinary universality says that you can write any program. Latent universality says that the solutions are already in the space, so a blind search over strings is searching a space where they exist. The machines below make this concrete enough to run searches and count costs.

Traces

What search finds

Working observations from evolutionary runs on these machines; not yet measured systematically.

  • Programs are found, not written. They are compact and odd, and reuse structure in ways a person would not: unmatched brackets used as restart loops, a blank cell used as a marker, toggles reused as counters, a lookup table encoded in the tail of the program.
  • Exactness on the training set is not enough. It can come from memorisation or from a length-general algorithm. Only the second counts, so programs are validated on inputs longer than any seen in training.
  • Solutions come out layered: a length-general part plus a bounded lookup part that saturates at the largest case in the sample. The data decide which part grows.
  • Search optimises what is measured. It exploits any regularity in the data. The practical response is to shape the pressure rather than the program: a curriculum on input length, stratified sampling, exactness required on all inputs up to a validation length, and an archive of every exact program.

Status and code

For LUTM-1 and LUTM-6, a constructive argument for fixed-interface universality is written out but not formally verified. Tests give finite evidence, not proof. Every program in the LUTM-6 and LU-A simulators is checked exact on all inputs up to 8 bits and on random 16-, 32- and 64-bit inputs. The open question is search: how program length, run time and the shape of the fitness landscape interact.

  • LUTM-1: simulators in Python, NumPy and CUDA, an island genetic algorithm and a program miner.
  • LUTM-6: machine, resumable genetic algorithm.
  • LUTM-6 and LU-A simulators (code): step-through browser simulators with the programs above.
