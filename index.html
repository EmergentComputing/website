Intelligence and computation should emerge from simple rules

We study how computation and intelligence emerge from simple dynamical systems, rather than from large, hand-designed architectures. Algorithms and models should be evolved, not designed. At most, a minimal core is designed and the rest is evolved. In nature, intelligence arose through evolution, from simple physical rules. Can the same happen in computation?

Our main work

Emergent Models

An Emergent Model is a machine-learning model built from a simple dynamical system, such as a cellular automaton. Complex computation emerges from iterating a simple local function over a hidden state many times. The state itself decides when the computation stops: a halting function reads it at every step, so the number of steps adapts to the input (adaptive computation time).

EM43 is a particular instance, built from a one-dimensional cellular automaton with 4 cell states. The figure shows it computing 2x for x = 9.

  1. Encode

    s₀ = p ⊕ E(x)

    The input is written into the initial state next to a learned pattern, the program p. In EM43, x is a red cell placed x cells right of the origin (green line).

  2. Iterate

    st+1 = f(st)

    A fixed local rule updates every cell from itself and its two neighbours, all cells at once. EM43's rule is a lookup table over the 64 possible neighbourhoods of a 4-state cell.

  3. Halt

    T = min{t : H(st) = 1}

    The run stops at the first step where a condition on the whole state holds, so larger inputs can take more steps. EM43 stops when blue cells are at least half of the non-blank cells.

  4. Decode

    y = D(sT)

    The output is read from the final state. In EM43, y is the distance of the rightmost red cell from the origin.

Training. In EM43, a genetic algorithm searches for the program, a finite portion of the initial state, and optionally the rule. Only the decoded output is scored; the dynamics in between are never supervised.

Why iterate

A feed-forward network has fixed depth: it does the same amount of computation for every input. Trained on sin x over [0, 4π], it fits the data and fails outside it (red). This is a limit of the architecture, not of training: on an unbounded domain, fixed-depth networks with bounded activations such as the sigmoid can uniformly approximate only a restricted class of functions, and periodic functions are not in it (van Nuland, 2024). A recurrent model can instead reduce x by 2π until x < 2π, and is correct everywhere (blue).

Recurrence is therefore a basic requirement for models that must generalise over open ranges. In the figure the loop is written by hand. In an Emergent Model it is part of the model: the halting function sets the number of steps for each input, and training decides how they are used.

EM43 learned x + 1, 2x, x mod 4, round(x/3) and x·(1 + x mod 2). A feed-forward network cannot represent x mod 4 or x·(1 + x mod 2) on all of ℕ. The models that work show a regular space-time geometry that scales with the input instead of changing: below, the same x mod 4 model at three input sizes. The paper calls this geometric grokking. Two-input multiplication a·b was not learned.

Other substrates in the paper

Game of Life

Conway's rule, fixed. Only the positions of two gliders are searched. Learns x + k exactly up to x = 200 after training on x ≤ 10, but random search does about as well as the genetic algorithm: similar programs have unrelated fitness.

The learned x + 2 program; input and output are 2×2 blocks on the diagonal.

CEM1D · continuous lattice

Nineteen real-valued cells and a rule with three learned coefficients. Controls CartPole with 735 ± 107 out of 800. The learned rule moves values through the lattice as travelling pulses.

Two impulse pairs under the learned rule. Red positive, blue negative.

CEM2D · Meta-Life

An 8×8 field with a fast and a slow channel; 35 rule and interface parameters. An agent adapts online when food turns into poison: meta-score 0.71, against 0.82 for a recurrent-network baseline. One cell next to the reward port stores the current phase.

Fast field after food and after poison, read from the paper's figure. Circled: the phase cell.

Theory. Some Emergent Models are latent-universal: with the rule, halting condition and interface fixed, every computable function is computed by some finite program. The solutions are guaranteed to exist in the search space; the theorem says nothing about how hard they are to find.

Research

Emergent and evolutionary computation

Emergent Models are our main line of work, not the only one. More broadly we study how small rules, search and selection produce programs that generalise. Pinned posts describe each line; notes, hypotheses and results follow.

Published

Emergent Models

Framework, latent-universality theorem, and experiments on discrete and continuous substrates: EM43, Game of Life, CEM1D, CEM2D.

 In progress

Latent-universal machines

LUTM-1, LUTM-6 and LU-A: small machines whose rule and interface never change. Only the program differs between tasks, and we measure how hard programs are to find.

 In progress

NCPU-EM

Neural cellular automata with one shared rule and a learned program per task. Builds on NCPU by Zhechev and Walas.
