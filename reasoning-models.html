Research · hypothesis

Reasoning models

Hypotheses about what makes a model reason procedurally, and how each could be tested. There are no results on this page yet; it will change as experiments come in.

By reasoning we mean, narrowly, deriving an answer by applying a sequence of operations rather than recalling a stored one. Several recent model families do this by iterating: adaptive-computation-time RNNs, reasoning language models, looped transformers, and small recursive models such as HRM and TRM. A Neural GPU trained on binary multiplication of up to 20-bit numbers generalises to 2000 bits. Emergent Models push the same idea to tiny local rules. The hypotheses below try to separate the ingredients.

H1 · iteration

Iteration is what enables extrapolation

Applying one update rule an input-dependent number of times lets a model represent rules that hold beyond the training range. A single forward pass of fixed depth can only interpolate within it.

Test. Same architecture and parameter count, fixed depth versus looped with adaptive halting. Arithmetic and string tasks; accuracy as a function of input length beyond training.

H2 · parameters per unit of time

The ratio q = Nparams / T̄ trades generalisation against trainability

Nparams is the size of the model in bits; T̄ is the mean number of update steps per prediction. Low q forces a short description run for a long time, which favours compressed, rule-like solutions. It also makes search harder: each parameter is reused at every step, so small changes compound and the landscape becomes rugged. Large feed-forward networks are the high-q limit.

Test. On EM43 and LUTM tasks, sweep program size and time budget. Measure extrapolation accuracy and search cost (evaluations until the first exact solution). Prediction: as q falls, both rise.

H3 · locality

Locality is an inductive bias separate from iteration

A rule that only sees neighbouring cells helps length generalisation on tasks with local structure and hurts tasks that must move information across the whole input. Early evidence: in NCPU-EM-1D, copy, shifts and increment stay near 100% at 26 bits after training on 16, while reverse falls to 1%.

Test. Looped transformers with sliding-window attention versus global attention, both with adaptive halting, on the same task set.

H4 · storage and computation

Facts and procedures want different models

Factual knowledge is largely incompressible and needs storage capacity; procedures are compressible. Large models suit retrieval, small iterated models suit procedures. One architecture to test: a large model that delegates procedure-like subproblems to a small, local, iterated core.

Test. Tasks that mix retrieval with multi-step computation, comparing a single model against model plus iterated core at equal compute.

Methods we are developing

  • Evolution strategies for training. Black-box optimisation where gradients through long loops are unstable or unavailable, including fine-tuning of language models. A hybrid splits the work: gradients for the rule, evolutionary search for programs and halting.
  • Search on rugged landscapes. Neutral drift, quality-diversity search over behavioural descriptors (halting time, space used), and library learning that reuses previously found programs as building blocks.
  • A generalisation signal without test data. Among programs that fit the training set exactly, prefer those whose space-time trajectories compress best. Testable now on EM43 and Game of Life tasks where only some exact fits extrapolate.
  • Parallel evaluation. Candidate programs are independent simulations, so search maps directly onto GPUs. See parallel and analog substrates.
