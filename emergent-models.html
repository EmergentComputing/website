Emergent Models

A model is a simple dynamical system: a state, a local update rule, a halting condition and a fixed way to write inputs and read outputs. Training searches for the initial state that makes the system compute the task.

Summary

  • An Emergent Model (EM) is a dynamical system, such as a cellular automaton, equipped with an encoder and a decoder. Prediction means: write the input into the state, iterate a fixed local rule until a halting condition holds, read the output.
  • The learnable object is mainly the initial state, called the program. The rule and parts of the interface can be learned too. Training uses evolutionary search, because the dynamics are recursive, often discrete and not differentiable.
  • Latent universality: there are EMs in which the rule and interface are fixed and any partial computable function can be realised by changing only the program. This is an existence result; it says nothing about how hard the program is to find.
  • Experiments use deliberately minimal models (tens to a few hundred parameters). The clearest result: a 140-bit cellular automaton trained on x ≤ 30 computes x + 1, 2x, x mod 4, round(x/3) and x·(1 + x mod 2) exactly up to x = 1000.
  • The framework is foundational. It does not propose a competitive architecture, and several tasks were not learned.

Source: G. Bocchese, N. Giacobbo, E. Guichard, J. Wiles, A. Devireddy, Emergent Models: Intelligence from Tiny Substrates, arXiv:2608.14019, 2026.

The model

An Emergent Model is a tuple M = (S, f, H, E, D, ⊕): a state space S over a graph of cells, a transition function f (usually local), a halting operator H, an encoder E, a decoder D, and an operator ⊕ that combines the program with the encoded input.

Inference is y = D(fT(p ⊕ E(x))), where T is the first step at which H fires. If it never fires, the output is undefined. The state provides memory; repeated application of f provides computation time.

Parameters fall into two groups. Soft parameters are the program: they live in the state and can change during inference. Hard parameters (rule, halting condition, interface) play the role of hardware: optimised during training, fixed during inference.

For streams of inputs, such as a control loop, a retention operator R turns the final state of one prediction into the program of the next: pi+1 = R(sT,i). The input stream can then change the computation itself, which is how the adaptive experiments below work.

Why iteration

The relevant notion of capacity here is global expressivity: which functions a model family can represent over their whole, possibly unbounded domain, not only on a compact region. A model that represents the generating rule extrapolates by construction; a local fit does not.

Feed-forward networks are limited in this sense. Universal approximation holds on compact domains; outside them, sigmoidal networks tend to constants and ReLU networks become linear, so functions like sin(x), eˣ or x mod 4 cannot be represented globally without task-specific engineering. Iterated systems with unbounded memory and time can be Turing-complete, which is the maximal notion of global expressivity in the discrete setting. Universality says nothing about trainability, but it removes a hard ceiling.

Latent universality

Theorem (latent universality). There exists an Emergent Model with a fixed rule, a fixed halting condition and a fixed interface on binary strings such that every partial computable function g : {0,1}* ⇀ {0,1}* is computed by some finite program state p.

The proof uses a universal Turing machine whose program and input occupy separate regions of the tape, so the initial state factors as p ⊕ E(x) and the encoder knows nothing about the program. A lemma extends the result to Conway's Game of Life through Rendell's universal construction.

The split matters for learning. The fixed interface defines only the syntax: where data is written and read. The program carries the semantics: which function is computed. Because the target function is unknown in advance, everything task-specific must live in the program, and search can vary programs without touching the interface.

Searchability. Programs are finite strings, so enumeration or random sampling eventually finds one that computes any given function. This is existence only: the search can be arbitrarily long. The experiments do not realise latent universality and none of their claims depend on the theorem.

Geometric grokking

In EM43 runs that generalise, the computation is visible as a regular space-time geometry that keeps the same shape as the input grows. For x mod 4, signals from the program region repeatedly shift the red marker until blue cells become the majority and the machine halts with the marker at the answer. The paper calls this geometric grokking. Whether it persists on harder tasks, or is partly an artefact of these tasks and this interface, is open.

Machines with a fixed interface in progress

The theorem guarantees that latent-universal models exist. These projects build concrete, small ones, to study how searchable their programs are.

  • LUTM-1: a one-tape Turing machine with 150 states, 16 symbols and 2,384 transitions. Every run starts from the tape p#x; the output is the bits right of # at halting. Verified programs include identity (5 bits), +1 (176 bits), ×2 (114 bits) and squaring (4,605 bits), all independent of input length. Simulators in Python, NumPy and CUDA, an island GA and a program miner.
  • LUTM-6: two tapes, four symbols, nine running states, 144 transitions. The program tape is read-only; input bits are written as fixed pairs, independent of the program. Known programs for NOT, reverse, increment and square.
  • LU-A: a language of ten operations on one data tape. The LUTM-6 and LU-A simulators run both side by side; every listed program is checked exact on all inputs up to 8 bits and on random 16-, 32- and 64-bit inputs.

Status. For both machines, a constructive argument for fixed-interface universality is written out but not formally verified; tests give finite evidence, not proof. The open question is search: how program length, run time and fitness landscape interact.

Neural cellular automata in progress

Here the rule is a small neural network shared by every cell, trained by gradient descent, and the program is a learned task-specific state in dedicated channels. One rule, many programs: a differentiable route to the fixed-rule, variable-program regime.

NCPU-EM-1D (demo) learns seven string tasks with one rule (10,150 parameters, 13 channels). Trained on strings up to 16 bits; semantic accuracy beyond that, synchronous updates:

The two tasks that fail are the two that need information carried across the whole input. With a local rule, information moves at bounded speed, so this is the expected failure mode, and a useful one to study.

Related code: NCPU-EM-2D (program tiles on a 2D grid), ncpu-computer (single-task baselines), ncpu-simplified (binary addition with single-cell inputs and outputs).

Parallel and analog substrates hypothesis

Local rules suit parallel hardware: each cell needs only its neighbours. Three directions, none tested yet.

Search on GPUs. Population-based search evaluates many candidate programs on the same inputs, which is a batch of independent simulations. LUTM-1 and LUTM-6 already run candidates in parallel on CUDA. Bit-packed cellular automata (two bits per EM43 cell) would put dozens of cells into one machine word.

CA-like hardware for arithmetic. The direction is hardware in which operations such as multiplication cost constant work per cell per step, with no instruction stream. Locality sets a floor: an output that depends on inputs d cells away needs at least d / r steps, with r the rule radius. For n-bit multiplication on a k-dimensional local array the latency therefore grows at least like n1/k. What can be constant is work per cell and throughput: a pipelined 1D array can emit one product bit per step (Atrubin, 1965). Constant latency needs non-local summation, such as threshold gates of unbounded fan-in or physical summation of currents or light. That trades time for precision and fan-in. Which regime is worth building, and whether search can find the rules, is open.

Analog media. CEM1D and CEM2D are continuous substrates. With real-valued cells the same framework could describe analog computing, but the paper gives no guarantee there. The deciding property for physical implementation is tolerance to noise; NCPU models trained with random asynchronous updates are a first step toward measuring it.

Open questions

  1. Can a rule be co-evolved across many tasks so that, once frozen, new tasks are solved by changing only the program?
  2. Which search methods work on landscapes where similar programs have unrelated fitness, as in Game of Life?
  3. Does the ratio of parameters to computation time govern a trade-off between generalisation and trainability? (See Reasoning models.)
  4. Is geometric grokking measurable, for example by the compressibility of space-time diagrams, and does it predict extrapolation?
  5. Does inherited state in adaptive controllers carry function, or do the hard parameters merely co-adapt to it? The paper proposes a two-run test.
